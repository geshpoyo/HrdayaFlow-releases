アプリが起動しない

Windows: SmartScreen で止まる

「WindowsによってPCが保護されました」 → 「詳細情報」 → 「実行」

Rust コア（hrdaya_core.dll）未検出 {#rust-core-dll}

リリース版（MSI / 配布 ZIP） では hrdaya_core.dll が同梱されていないと起動直後に警告が出て、保存・別名保存・書き出しは無効 になります（CE-01）。不完全な ZIP だけ保存してデータが壊れるのを防ぐためです。

開発版（flutter run） では DLL が無くても起動できますが、保存は map.json のみのフォールバックになり、アセットが ZIP に入らないことがあります。

症状対処
起動時「Rust コアが見つかりません」再インストール。hrdaya_flow.exe と同じフォルダに hrdaya_core.dll があるか確認
設定に「Rust コア: 未接続」設定 → Rust コア → 再接続を試行。直らなければ DLL 配置を確認
flutter run で未接続下記のビルド手順。誤アーキの DLL（x86 など）が core/target に残っていると error 193 になることがある
リリースビルド / MSI が失敗するinstaller/build.ps1 が hrdaya_core.dll 欠落で exit 1。先に cargo build --release
cd core
cargo build --release
cd ../app
flutter run -d windows

Windows では Release 出力の DLL は通常次にコピーされます。

app/build/windows/x64/runner/Release/hrdaya_core.dll

詳細: リポジトリ内 docs/debug/rust-ffi-init.md

flutter run でクラッシュ即終了

Flutter SDK の version 不一致。flutter doctor で確認。3.27 系を推奨。

ファイル関係

ファイル整合性エラー（CE-03） {#map-validation}

読み込み直後、または保存前に Rust コアが map.json の整合性を検査します。問題があるとダイアログが表示されます（自動修復はしません）。

種別例意味
エラーcyclic_hierarchy親子関係（hierarchy エッジ / コンテナ members）に循環
エラーorphan_edge_source / orphan_edge_target存在しないノード ID を指すエッジ
エラーduplicate_node_id / duplicate_edge_id同一 ID の重複
警告unknown_kind未知のノート種別（将来互換のため読み込みは継続）
警告invalid_writing_mode 等style / canvas の enum 値が想定外
状況対応
読込後にエラー表示マップは開いたまま。循環や孤立エッジを手で直すか、バックアップから復元
保存前にエラー表示キャンセル で保存中止。このまま保存 で上書き（非推奨・データ不整合のまま残る）
Rust 未接続検証はスキップ（開発ビルドのみ。リリースでは CE-01 により保存自体がブロック）

手編集や他ツール由来の JSON で警告だけ出ることはあります。unknown_kind は v0.4 先行フィールドの可能性があります。

.hrf が開けない

原因対応
バージョン不一致 (新 → 旧)受信側を最新に
ZIP 破損7-Zip で開けるか試す。ダメなら復旧不可
パスに非 ASCII 文字UTF-8 filename Flag が立っているはずだが、古い Windows は弱い
アンチウィルスがブロック例外設定

自動保存が効かない

設定 → 一般 → 自動保存 → ON 確認。データフォルダの書き込み権限も確認。

.hrf を開いた直後に「アセットの整合性が確認できません」 {#hash-mismatch}

manifest の SHA256 と実 ZIP 内容が不一致。M7 (2026-05-30) の機能で安全側に倒している。

状況対応
自分で作ったマップで出るバグ報告 (manifest 生成と書き込みの順序)
受け取った .hrf で出る送り主に再生成してもらう。「信頼して展開」は最終手段
アセット 1〜2 件のみAsset Extractor で個別に「信頼して展開」

naked JSON を保存したのに .hrf になる

挙動は仕様。.json は読み込み専用扱いで、保存時は ZIP コンテナに昇格する。.json のまま保存したいなら CLI:

hrf export input.hrf --format naked-json --output map.json

キャンバス操作

ノートが画面外に消えた

⌨ Ctrl + 9 で全体表示。それでも見えなければ Outline パネルから選択 → ⌨ End で重心ジャンプ。

ドラッグしてもノートが動かない

原因対応
ノートが Layer ロックされているOutline → Layer → 🔒 を解除
Sticky フラグが立っているInspector → Common → Sticky OFF
Container 内のノートが Container ごと動く挙動子だけ動かしたいなら Alt + ドラッグ

Dot が勝手に消える

Dot に接続するエッジが 0 本になると Dot は 自動削除 される (ゴミ Dot 散乱防止)。ノート削除やエッジ単独削除のあとに起きることがある。意図しない場合は Ctrl + Z で戻す。仕様の詳細は 03-edges-and-connections › ナイフでエッジリルート-dot-中継。

スナップが意図しない位置で吸着する

Magnetic Snap が ON のノートが多い。要らないノートは Inspector → Effects → Magnetic OFF。 一時的にスナップ無効: Alt + ドラッグ 。

Tab キーが pie メニューを呼ばない

🚧 pie integration (#5) は 未実装 (pie-integration.md)。Tab は子ノート派生だけが動く。

エッジ関係

エッジが引けない

接続ハンドルはノードの エッジ部分にホバー で出る。中央にホバーしても出ない。

エッジ端が外れる

K-gsr10 (2026-04 修正) でほぼ解消。再現したらバグ報告。

Inspector / 書式

書式変更が効かない

複数選択で 共通プロパティ以外 を変えようとしている可能性。1 つずつ選んで試す。

Format Panel が出ない

Inspector パネル自体が閉じている → ⌨ Ctrl + Shift + I で開く。

Undo / 履歴

Ctrl + Z が効かない

原因対応
編集モード中 (テキスト入力)Esc で抜けてから
履歴上限 (500 件) を超えた設定で上限を増やす
履歴ビューアで分岐した履歴ツリーを再確認

履歴ビューアが空

⌨ Ctrl + Alt + Z で開けるが、起動直後は空。何か操作すると埋まる。

検索

Ctrl + F でヒットしない

原因対応
大小区別が ON検索ダイアログで OFF
種別フィルタが効いている「すべて」に戻す
Container が折りたたまれていて中身が対象外設定「Container 内も」を ON

AI

AI Panel で「stub のみ」と出る

LLM (Ollama / PrudeLLM) に接続できていない。

原因対応
Ollama が起動していないollama serve
ポートが違うSettings → AI → Ollama URL 確認
PrudeLLM API キー未設定Settings → AI → PrudeLLM 設定

AI service 自体が動かない

curl http://127.0.0.1:8765/health

{"status":"ok"} が返らないなら:

  1. ポート 8765 が他プロセスに使われていないか (netstat -ano | findstr 8765)
  2. Python / pip 依存が揃っているか (pip install -r ai_service/requirements.txt)
  3. Settings → AI → 「自動起動」を OFF にしてから手動で起動

詳細: 10-ai-features › service-startup

LLM の応答が JSON 不正

1 回リトライ → 2 回目失敗で stub にフォールバック。LLM のシステムプロンプトを設定 → AI → プロンプト編集 で調整。

原因対応

開発時のログノイズ

[ERROR] Failed to update ui::AXTree がコンソールに溢れる

症状: マウス移動するたびに以下が大量に出る:

[ERROR:flutter/shell/platform/common/accessibility_bridge.cc(114)]
Failed to update ui::AXTree, error: NN will not be in the tree and is not the new root

原因: Flutter Windows shell の AXTree (アクセシビリティツリー) 同期 race。Tooltip などホバーで Overlay を生成・破棄する widget の通知順序が Windows shell の AX 処理と競合し、Failed to update ログを出す。

実害:

  • ❌ アプリ動作には影響なし (機能・表示・データすべて正常)
  • ❌ スクリーンリーダー (Windows ナレーター等) には影響あり (一時的に同期取れない)
  • ⚠ コンソールが汚れて他のログが読めなくなる ← これが実害

対処: 開発時は必ず scripts/dev-run.ps1 でラップして起動する。

# 直接 flutter run ではなく:
pwsh scripts/dev-run.ps1
pwsh scripts/dev-run.ps1 --release

このスクリプトは AXTree / accessibility_bridge / 既知の build warning を stderr フィルタで抑制し、本当に重要なログだけを表示します (Dart エラー、[FLUTTER] レベルの警告、HrdayaFlow starting 等のステートメッセージは色付きで表示)。

根本対処 (将来):

  • Flutter framework 側の Tooltip overlay 実装が修正されるのを待つ
  • もしくは全 Tooltip を StableHoverTooltip (app/lib/widgets/stable_hover_tooltip.dart) に置換する作業を継続的に進める (高密度で hover される箇所から優先)
