セットアップ

詳細: 開発環境セットアップ_Windows.md（開発リポジトリ。この vault には未収録）

最低限:

必要バージョン入手
Flutter SDK3.27+flutter.dev
Rust toolchain1.78+ (stable)rustup
Python3.11+python.org
Visual Studio Build Tools2022 (Windows)visualstudio.microsoft.com
Git任意git-scm.com
git clone https://github.com/<owner>/HrdayaFlow.git
cd HrdayaFlow

ビルドと起動

Flutter app (UI)

cd app
flutter pub get
flutter run -d windows           # debug
flutter run -d windows --release # release

ホットリロード: ターミナルで r、ホットリスタート: R、終了: q。

Rust core

cd core
cargo build                     # debug
cargo build --release           # release
cargo test                      # 全テスト
cargo test --test hrf_assets_ordering_test  # 特定 test
cargo clippy -- -D warnings     # lint

flutter run 時に Rust DLL が古いと FFI エラー。Rust 側を変更したら 必ず cargo build してから flutter run。

Python AI service

cd ai_service
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8765 --app-dir src
pytest tests/                   # 全テスト

FFI コード生成

Rust 側 API (core/src/api.rs) を変更したら:

cd app
flutter_rust_bridge_codegen generate

app/lib/bridge_generated.dart/ が更新される。git status で差分確認、commit。

CLI ツール {#cli}

core/src/bin/ 配下にスタンドアロン CLI。

hrf (汎用)

hrf import input.opml --output output.hrf
hrf export input.hrf --format markdown --output out.md
hrf hash input.hrf                    # 内部 SHA256 一覧
hrf diff before.hrf after.hrf         # JSON Patch 出力
hrf apply-patch base.hrf patch.json   # JSON Patch 適用
hrf list-assets input.hrf             # アセット一覧

bench_k11_gate

cargo run --bin bench_k11_gate --features bench-gate

K11-bis (JSON Patch undo) のベンチマーク。docs/may-2026/k11-bis-json-patch-crate.md 参照。

budget_check.dart

cd tools/budget_check
dart run lib/main.dart --baseline baseline.json --current current.json

CI で .github/workflows/budget-gate.yml から呼ばれる。詳細: [[#budget-gate]]

MCP Server (HrdayaFlow を Claude / Cursor から操作)

app/lib/mcp/ で HTTP ベース MCP wrapper をホスト。

起動

アプリ起動時に自動で localhost:3737 にホスト (Settings で OFF 可)。

stdio fallback: rust/hrdayaflow-mcp/ バイナリを claude_desktop_config.json に登録。

{
  "mcpServers": {
    "hrdayaflow": {
      "command": "C:\\path\\to\\hrdayaflow-mcp.exe",
      "args": []
    }
  }
}

公開ツール

ツール用途
read()現在開いているマップ全体 (map.json)
find_node(id)1 ノート取得
find_edge(from, to)エッジ取得
bulk_apply(operations)操作配列を一括実行
bulk_patch(patch)RFC 6902 JSON Patch 適用
screenshot(area)領域スクショ取得
list_task_listsプランナー: リスト一覧
list_tasksプランナー: スマートリスト / リスト別 / 完了済み
add_taskプランナー: タスク追加（自然文可）
complete_taskプランナー: 完了 / ロール / undo

プランナー操作の使い方は 12 Planner。マップ系の詳細仕様: docs/v0-1-1/c-mcp-tools/。

設定: hand-rolled JSON-RPC

メモリにあるとおり、rmcp crate は使わない。rust/hrdayaflow-mcp/ で hand-rolled JSON-RPC proxy。理由: 依存最小、Rust core との型共有。

Budget Gate (CI 性能ガード) {#budget-gate}

.github/workflows/budget-gate.yml で PR ごとに走る。

計測対象

docs/performance-budgets.yaml に定義:

budgets:
  app_size_mb:        { target: 80,  hard_limit: 120 }
  startup_ms:         { target: 2000, hard_limit: 3000 }
  open_1000nodes_ms:  { target: 1500, hard_limit: 2500 }
  memory_idle_mb:     { target: 200, hard_limit: 350 }
  ...

違反時の挙動

enforcement セクションで定義 (M12, 2026-05-31):

状態exit codePR ステータス
全て target 内0✅ pass
target 超 / hard_limit 内1⚠ warning (merge 可)
hard_limit 超2❌ fail (merge 不可)
baseline 不在3🚧 baseline 生成のみ
設定エラー4エラー

STRICT_OVERRIDE=1 環境変数で warning も fail に昇格。

アーキテクチャ Lint (senastra_architect) 🔌

Senastra 側に依頼中 (Senastra への要望メモ（別資料・現在は未整備）)。完了後 CI に組込:

  • 循環依存検出
  • god-module 警告 (1500 LOC / 40 public API 超)
  • shared/ 肥大化警告

i18n (翻訳寄稿) {#i18n}

  1. app/lib/l10n/intl_ja.arb を origin として参照
  2. intl_<lang>.arb を新規作成 (例: intl_zh.arb)
  3. すべての key を翻訳
  4. flutter gen-l10n で lib/l10n/intl_*.g.dart を再生成
  5. テスト: flutter run -d windows で言語切替して確認
  6. PR

寄稿フロー

  1. Issue を立てる (or 既存 issue を選ぶ)
  2. ブランチ: feat/<short-desc> / fix/<short-desc> / docs/<short-desc>
  3. PR を作る (template が CHECK リスト出してくれる)
  4. 全テスト pass + budget gate pass + clippy clean
  5. レビュアーアサイン → 1 approve で merge

詳細: .github/CONTRIBUTING.md 🚧

デバッグ Tips

症状確認
FFI Result がエラーRUST_LOG=debug flutter run で Rust ログ表示
Layout が崩れるflutter inspector (DevTools) でツリー検査
AI service 接続失敗curl http://127.0.0.1:8765/health
ZIP I/O エラー7-Zip で .hrf を開いて中身確認
Undo が壊れたCtrl + Alt + Z で履歴ビューア → どこから壊れたか確認

リリースフロー

詳細: release-channel-flow.md

要点:

  1. CHANGELOG.md 更新
  2. app/pubspec.yaml / core/Cargo.toml / installer/ の version を bump
  3. git tag v<x.y.z> → push
  4. CI が installer ビルド + GitHub Release 作成
  5. winget-manifest/ 更新
