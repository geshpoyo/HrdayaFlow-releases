01 概要とアーキテクチャ

← 目次に戻る | 次の章: はじめに →

HṛdayaFlow とは

中心から智慧が流れ出す曼荼羅的マインドマップ。

HṛdayaFlow は、テキスト・画像・動画・音声・コード・Web 埋め込みを 一枚に束ね、関係線で結ぶ デスクトップ型マインドマップです。フリーフォーム (どこにでも置ける) とオートレイアウト (整然と並べる) のハイブリッドで、フリーフォーム系のキャンバスの自由度と、X-Mind / FreeMind のような構造化を両立させます。

名前の由来

  • Hṛdaya (フリダヤ) — サンスクリットで「中心 / 心臓 / 本質」
  • Flow — 流れ / 思考のフローネス
  • 中央から智慧が放射状に拡がるマンダラのイメージを、UI のシンボルにしている

競合との位置づけ

製品自由配置構造化マルチメディアAI 連携備考
フリーフォーム系 MM◎△××自由度は強いが、構造もエクスポートも限定的
XMind / MindMeister△◎△△構造化は強いが、自由配置やノートに弱い
Obsidian Canvas◎△◎△Markdown 連携は強いが、デスクトップ専用ノードは限定的
Miro / Mural◎○◎△コラボ前提で個人ローカル向きでない
HṛdayaFlow◎◎◎◎全部入り。ローカル・オフライン優先

アーキテクチャ

┌──────────────────────────────────────────────────────────┐
│  Flutter Desktop (Dart)                                  │
│  ├─ canvas / nodes / edges / panels / inspector          │
│  ├─ ジェスチャー・ショートカット・テーマ                 │
│  └─ Undo/Redo (canvas_undo_adapter)                       │
└──────────────────────────────────────────────────────────┘
                       ↑↓ FFI (flutter_rust_bridge 2.12)
┌──────────────────────────────────────────────────────────┐
│  Rust Core (hrdaya_core)                                 │
│  ├─ graph / layout / io (.hrf v0.2 ZIP)                  │
│  ├─ importers (Mermaid / OPML / XMind / FreeMind / ...)  │
│  ├─ exporters (PDF / SVG / PNG / Markdown / JSON Canvas) │
│  └─ JSON Patch (RFC 6902, json-patch crate)              │
└──────────────────────────────────────────────────────────┘
                       ↑↓ HTTP / WebSocket (port 8765)
┌──────────────────────────────────────────────────────────┐
│  Python AI Service (FastAPI)                             │
│  ├─ /api/generate-map (テキスト → マップ)               │
│  ├─ /api/summarize-map (マップ → テキスト)              │
│  └─ Backend: stub / PrudeLLM / Ollama                    │
└──────────────────────────────────────────────────────────┘

各層の責務

層技術役割
UIFlutter Desktop (Dart 3.x)キャンバス描画・ジェスチャー・ノード編集・パネル
CoreRust (flutter_rust_bridge)グラフ構造・レイアウト演算・I/O・形式変換・JSON Patch
AIPython (FastAPI)LLM 接続・テキスト ⇔ マップ変換・suggest

なぜこの 3 層構成か

  • UI に Flutter — Windows / macOS / Linux 同一コードベース、リッチ描画 (CustomPaint)、ホットリロードで反復速度
  • Core に Rust — ZIP I/O、SHA256、JSON Patch、レイアウトアルゴリズムなど CPU バウンド処理を高速・安全に
  • AI を Python に隔離 — LLM ライブラリエコシステムが豊富、バージョン非依存、別プロセスでクラッシュ隔離

システム要件

動作環境 (推奨)

OS状態備考
Windows 10/11 (x64)✅ 主サポートinstaller/ で MSI 提供
macOS 12+ (Apple Silicon / Intel)🚧 動作するがインストーラ未配布flutter build macos で生成可
Ubuntu 22.04+ (x64)🚧 動作するがパッケージ未配布flutter build linux

ハードウェア (推奨)

  • CPU: 4 コア以上 (Rust core はスレッドプール活用)
  • メモリ: 8 GB 以上 (1000 ノード前後で 500 MB 程度を消費)
  • GPU: なくても動くが、ズーム / アニメーションが滑らかになる
  • ストレージ: SSD 推奨 (起動 < 2 秒、.hrf 保存 < 200 ms 目標)

詳細予算は HrdayaFlow/docs/performance-budgets.yaml（開発リポジトリ） と budget gate (04-developer-guide › budget-gate) を参照。

外部サービス (任意)

  • Ollama (ローカル LLM) — localhost:11434 で動作中なら自動検出
  • PrudeLLM (ホスト LLM) — API キー設定で利用可
  • 未設定でも全機能は動く (AI のみ stub にフォールバック)

ファイル形式

主形式は .hrf v0.2 (ZIP コンテナ)。詳細は 11-files-and-interop。
