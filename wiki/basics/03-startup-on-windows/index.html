開発時の起動手順（開発者向け）

目次

⚠ この章はソースからビルドして動かす人向けです。
インストーラーで導入した場合、ここに書かれた手順は不要です。
Python の AI サービスも Rust コアもインストーラーに同梱されており、
手で起動する必要はありません。普通に使う手順は 02-getting-started を参照してください。

環境構築済みの前提で、毎日の開発で使う起動手順をまとめたものです。
初回セットアップは 開発環境セットアップ_Windows.md を参照してください。

構成の全体像

[Flutter アプリ]  ←FFI（将来）→  [Rust コア]
      ↕ HTTP / WebSocket
[Python AI サービス]  ←→  PrudeLLM / Ollama

現状（Phase 1）は Flutter アプリ単体で動きます。
AI 機能を使うときだけ Python サービスも起動してください。

Flutter アプリの起動（メイン）

cd C:\Users\geshtalt\dev\HrdayaFlow\app
flutter run -d windows

よく使うオプション:

コマンド説明
flutter run -d windowsWindows デスクトップで起動
flutter run -d windows --debugデバッグモード（デフォルト）
flutter run -d windows --releaseリリースビルドで起動（描画が速い）
flutter run -d windows --profileパフォーマンス計測用

起動中のショートカット（ターミナル上）:

キー操作
rホットリロード（コード変更を即反映）
Rホットリスタート（状態をリセットして再起動）
q終了
hヘルプ表示

ヒント: コードを変更したら r を押すだけで再起動不要で反映されます。

Python AI サービスの起動（AI 機能を使うとき）

cd C:\Users\geshtalt\dev\HrdayaFlow\ai_service
.\.venv\Scripts\Activate.ps1        # 仮想環境を有効化
uvicorn main:app --reload --host 127.0.0.1 --port 8765 --app-dir src
  • --reload により、src/ 内のコードを変更すると自動で再起動します
  • Flutter アプリからは http://127.0.0.1:8765 で通信します

起動確認:

# 別の PowerShell で
curl http://127.0.0.1:8765/health
# → {"status":"ok"} が返れば正常

Rust コアのビルド（コアのコードを変更したとき）

現状 Flutter と直接つながっていないため、変更を確認したいときは単体でビルドします。

cd C:\Users\geshtalt\dev\HrdayaFlow\core
cargo build           # デバッグビルド
cargo test            # テスト実行
cargo build --release # リリースビルド

まとめ：毎日の開発フロー

# 1. Flutter アプリを起動（これだけで開発できる）
cd C:\Users\geshtalt\dev\HrdayaFlow\app
flutter run -d windows

# 2. AI 機能も触るとき：別の PowerShell タブで
cd C:\Users\geshtalt\dev\HrdayaFlow\ai_service
.\.venv\Scripts\Activate.ps1

トラブルシューティング

現象対処
flutter: command not foundFlutter SDK の bin が PATH にない → 環境変数を確認
ビルドエラー link.exe not foundMSVC C++ ビルドツール未インストール → セットアップ手順 §1
flutter run が遅い初回はパッケージ取得があるため正常。2回目以降は速くなる
AI サービスに繋がらないPython サービスが起動しているか確認。ポート 8765 が使われていないか確認
ホットリロード（r）が効かないR（ホットリスタート）を試す。それも効かなければ q で終了して再起動

保存ファイルについて

  • 保存形式: .hrf（ZIP アーカイブ、内部に map.json）
  • デフォルト保存先: ファイルダイアログで任意の場所を選択
  • バックアップ: 保存時に .hrf.bak が同じフォルダに自動生成されます（Phase 1 以降）
