主形式 .hrf v0.2 と、外部形式 7 種との往復。PDF / PNG / SVG での書き出し。

ネイティブ形式: .hrf v0.2

.hrf は ZIP コンテナ。1 ファイルでマップ + アセット + サムネイル + 任意で履歴をパッケージ化。

物理レイアウト

mymap.hrf  (ZIP, UTF-8 filenames)
├── manifest.json          ← メタデータ
├── map.json               ← マップ本体
├── thumbnail.png          ← 512×512 プレビュー
├── assets/
│   ├── {sha256}.png       ← 内容ハッシュ名（同一バイト列は 1 ファイル、CE-04）
│   ├── {sha256}.jpg
│   ├── images/<uuid>.png  ← 旧形式（読み込み互換）
│   ├── videos/<uuid>.mp4
│   ├── audio/<uuid>.m4a
│   ├── text/<uuid>.md     ← 長文 markdown body
│   └── files/<uuid>.<ext>
├── history/               (任意)
│   └── snapshots/<epoch>.json
└── originals/             (任意)
    └── <filename>          ← import 元

manifest.json

{
  "format": "hrdaya-flow",
  "formatVersion": "0.2.0",
  "minViewerVersion": "0.2.0",
  "created": "2026-04-28T10:30:00+09:00",
  "modified": "2026-04-28T18:42:11+09:00",
  "generator": { "name": "HṛdayaFlow", "version": "0.0.3" },
  "platform": "windows",
  "documentId": "uuid-v4",
  "thumbnail": "thumbnail.png",
  "assetManifest": [
    { "path": "assets/images/abc.png", "sha256": "...", "size": 12345, "mime": "image/png" }
  ]
}

assetManifest は 改竄検知用。読み込み時に SHA256 を再計算して照合する (M7、03-troubleshooting › hash-mismatch)。

アセット重複排除（CE-04、2026-05-21〜）

保存時、Rust コアが各アセットの SHA-256 を計算し、ZIP 内では assets/{sha256}.{ext} に 1 回だけ格納する。同じ画像を複数ノードに貼っても物理ファイルは 1 つ。

ノード側の参照（新規保存）ZIP 内の実体
sha256:abc123…（64 文字 hex）assets/abc123….png 等
assets/images/{uuid}.png（旧）そのまま（読み込み互換）
uuid:{uuid}（旧）assets/images/{uuid}.* 等へ解決

取り込み時の Dart（ImageIngestionService 等）は従来どおり隣接 assets/images/<uuid>.ext を作る。保存時に Rust がハッシュ化・dedup するため、Dart 側の変更は最小限。

読み込み時、sha256: / uuid: 参照は map.json 向け JSON では assets/... パスへ展開され、キャンバス表示と再保存がそのまま動く。

map.json 構造

{
  "id": "uuid",
  "title": "マイマップ",
  "description": "...",
  "canvas": { "unit": "px", "background": "#fff", "gridSize": 16, "viewport": {...} },
  "nodes": [ ... ],
  "edges": [ ... ],
  "styles": [ ... ],
  "submaps": { "id1": { ... } },
  "layers": [ ... ]
}

詳細スキーマは docs/cursor-hrf-v0.2-interop.md 参照。

後方互換

入力動作
.hrf v0.2 (manifest.json あり)✅ フル機能
.hrf v0.1 (map.json のみ ZIP)✅ 自動変換、保存時は v0.2 化
裸 JSON (.json 拡張子)✅ map.json として読み込み (アセット参照は外部 URL のみ)
不明な拡張子の ZIPmanifest 検査して hrdaya-flow 判定したら開く

保存

⌨効果
Ctrl + S上書き保存
Ctrl + Alt + S名前を付けて保存
(自動)5 分ごと or 操作 50 件ごと

自動保存

設定 → 一般 → 自動保存。OFF / 1 分 / 5 分 / 操作ごと。

保存先

既定: <Documents>/HrdayaFlow/。Settings で変更可。

名前を付けて保存の初期ファイル名

既存の .hrf を開いているタブで 名前を付けて保存 を実行すると、保存ダイアログのファイル名欄には現在のタブ名（例: project_restore.hrf）が入ります。新規の無題タブだけ untitled.hrf になります。

開く

Windows ファイル関連付け

MSI でインストールした Windows 版では、Explorer で .hrf をダブルクリックすると HrdayaFlow が起動し、そのファイルを現在のタブへ読み込みます。起動後に「無題」のままになる場合は、ファイルパス引き渡しまたは起動引数処理の不具合として扱います。

⌨効果
Ctrl + Oファイルダイアログ
Ctrl + PQuickOpen (09-search-and-outline › quickopen)

D&D で .hrf / .json をウィンドウへ → HrdayaFlow ドキュメントとして開く。空の無題タブならそのタブを再利用し、既に作業中のタブなら新しいタブで開く。

.hrf / .json は添付ファイルノートにはなりません。Markdown や画像などの通常ファイルだけが、埋め込み / 外部リンクを選んでキャンバス上のファイルノートになります。

Import: 他形式 → HrdayaFlow

メニュー → ファイル → インポート → 形式選択 (or 拡張子で自動判定)。

形式拡張子サポート備考

JSON Canvas (Obsidian).canvas✅nodes + edges 双方向
OPML.opml✅アウトラインプロセッサ

他のフリーフォーム MM.scap✅JSON ベース

Auto-detect

拡張子 + magic byte で形式自動判定 → 「.canvas を JSON Canvas として開く?」確認 → OK で読込。

取り込み後の整形

import 直後はノートが密集していることが多い。Ctrl + Alt + G (Container 内 Auto Layout) や、トップレベルで「整列」メニューから tree-down / radial を選ぶと整う。

Export: HrdayaFlow → 他形式

メニュー → ファイル → エクスポート → 形式選択。

形式用途備考
PDF印刷・配布A4/A3、viewport / fullmap、ベクター
PNGプレゼン素材解像度指定、背景色指定
SVG編集可ベクターInkscape などで再編集可能
Markdown outlineObsidian / Notion階層を - インデントで
MermaidGitHub READMEmindmap / flowchart
JSON CanvasObsidian Canvas双方向

PDF / PNG / SVG の細かい設定

エクスポートダイアログで:

  • スコープ: 全マップ / 現在のビューポート / 選択範囲
  • 用紙: A4 / A3 / カスタム (PDF のみ)
  • 解像度: 96 / 144 / 300 dpi (PNG のみ)
  • 背景: 白 / 透明 / 指定色
  • マージン: 0 / 5 / 10 / 20 mm
  • フォント埋め込み: PDF のみ ON/OFF (ファイル肥大に注意)

PDF 出力

  • pdfium-render ベース
  • ベクター出力 (拡大しても劣化しない)
  • 日本語 / 中文 / 韓文フォント対応
  • リンクはクリック可能 PDF リンクに変換
  • 詳細: core/src/export/pdf.rs

Print

⌨ Ctrl + P (印刷) → OS 標準ダイアログ → プリンタ選択 or 「PDF として保存」。

Asset Extractor (アセット取り出し)

.hrf から内蔵アセット (画像 / 動画 / 音声) を取り出すダイアログ。

メニュー → ファイル → Asset Extractor

│ 検索: [          ]   ☑ SHA256 検証          │

│ ☑ img | 顧客 A.png        | 1.2 MB | 参照: 3│
│ ☑ vid | デモ.mp4          | 24 MB  | 参照: 1│

│ ☑ 同名はリネーム                            │
│            [ キャンセル ] [ 取り出し ]      │
└──────────────────────────────────────────────┘

詳細: M7 (2026-05-30) で check-then-write 反転 (03-troubleshooting › hash-mismatch 参照)。SHA256 不一致時は ファイルが書き込まれない。

信頼して展開 (Trust)

SHA256 不一致でも「危険を承知で展開」できるエスケープハッチ。確認ダイアログ後に動作。

Naked JSON Fallback

.json 拡張子のファイルを開いた場合:

  1. ZIP として開く試行 → 失敗
  2. JSON として直接 parse → map.json として扱う
  3. アセット参照は 外部 URL のみ 有効 (ZIP 内アセットは存在しないため)
  4. 保存時は .hrf (ZIP) として保存 (上書きしたければ「名前を付けて保存」)

大きなアセットの扱い

状況動作
50 MB 以下.hrf 内に埋め込み
50 MB 超 (既定)外部リンク参照 (originUrl のみ) を推奨ダイアログ

閾値は Settings で変更可 (10〜500 MB)。

ファイル比較・履歴

CLI ツール:

hrdaya diff before.hrf after.hrf > patch.json
hrdaya apply-patch base.hrf patch.json --output result.hrf
hrdaya hash mymap.hrf  # SHA256 一覧

詳細: 04-developer-guide › cli
