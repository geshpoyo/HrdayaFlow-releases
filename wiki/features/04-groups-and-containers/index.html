06 グループと Container

← 05 エッジ | 目次 | → 07 Inspector

複数ノートを「箱」にまとめる仕組みが Container (実体グループ)、視覚的なまとまりだけが Frame (装飾)。サブマップ昇格でテーマ別マップを切り出せる。

v0.0.4 親子関係再設計 (2026-05-17): Container と Frame の「子の所有」は EdgeKind.hierarchy の親子関係 Edge で表現されるようになりました。

  • Frame も子を持てる ようになり、Frame を移動すると親子関係 Edge で繋がった子ノートも追従します
  • Container.containerMembers[] は derived cache (hierarchy edges から再生成される派生値) に格下げ。schema 後方互換のため .hrf 上にも保存され、v0.1 系の reader でも開けます
  • Container/Frame の中の階層構造はそのまま保持される (例: tesst → test2 の親子関係がある状態で Container 化しても、関係は維持)
  • 詳細は docs/v0-0-4/o-hierarchy-redesign/README.md

用語の整理

概念実体折りたたみ子の所有用途
Frame装飾矩形×✅ (hierarchy edges)視覚的な背景・囲み、親移動で子追従
Containerグループ実体✅✅ (hierarchy edges、members[] は cache)論理的なまとまり、折りたたみ可能、サブマップ昇格可
Submap別マップ(Container として現れる)✅大きな概念を別キャンバスに

Container を作る

既存ノートをまとめる

  1. 🖱 複数ノート選択 (矩形ドラッグ or Shift + クリック)
  2. ⌨ Ctrl + G
  3. → 周囲を囲む Container が生成、選択ノートのうち 階層のトップ (親が選択外、または親なし) だけが Container の直接子として hierarchy Edge で接続される
  4. → 選択内の既存親子関係はそのまま温存される (例: A→B が既にあり、A, B を一緒に Container 化すると Container → A → B の階層になる)

空の Container を作る

⌨ Ctrl + Shift + N → ピッカー → G (Container)

解除

  • ⌨ Ctrl + Shift + G: Container 自体を削除し、直接子のノートを独立化 (Ungroup)
  • ⌨ Alt + P (選択中ノートに対して): その親 hierarchy Edge を 1 本削除。Container の中から特定ノートだけを外したい場合に使う (子孫は引き続き選択ノートに従属する)

Container の操作

操作効果
🖱 タイトルバーをダブルクリックラベル編集
🖱 タイトルバーの ▶ / ▼折りたたみ / 展開
🖱 Container 自体をドラッグ中の子孫すべてが推移的に追従 (hierarchy edges 経由)
🖱 子ノート単独をドラッグContainer が子の bbox を内包するよう自動再フィット (v0.0.4 P-01)
🖱 Container のリサイズハンドル (4 辺 + 4 角)8 方向リサイズ可能。ただし子 bbox + padding を下回るサイズには縮められない (v0.0.4 P-02)
👁 Container 矩形内に親子関係のないノートが重なっている赤い破線枠で警告、Tooltip「Container 内にありますが親子関係はありません」(v0.0.4 P-03)
⌨ G (Blender 風 grab) でアクティブが Container同上、子孫が追従
⌨ 矢印キー nudge で Container が選択中同上、子孫が追従
🖱 子ノートを Container 外にドラッグmembers から自動的に外れる (旧挙動)
🖱 ノートを Container にドラッグオーバーmembers に追加 (吸い込み)
⌨ Ctrl + Alt + GContainer 内を Auto Layout
⌨ Alt + P (Container の子に対して)親子関係 Edge を 1 本解除、子が Container から離脱

Container プロパティ

Inspector に出る項目:

プロパティ説明
labelContainer のタイトル (ヘッダーに表示)
collapsed折りたたみ状態 (永続化)
layoutHintfreeform / tree-down / tree-right / radial
padding子ノートとの余白
fillColor / borderColor見た目
autoSize子の範囲に自動フィットするか

Container の追従動作

  • ✅ Container を移動 → 子も同じだけ動く
  • ✅ Container をリサイズ → 子は固定 (自動フィット ON なら逆)
  • ✅ 子を選択 → Container は選択されない (操作対象は子)
  • ✅ Container 自体を選択するには ヘッダーバーをクリック

サブマップ (Submap) 昇格

Container を 「別のマップ」として開く 機能。複雑な部分を分離して整理。

昇格手順

  1. Container を右クリック → 「サブマップとして開く」
  2. 新しいタブが開き、Container の中身が「ルートマップ」として表示
  3. 親マップ側では Container がリンクアイコンに変化

サブマップを再び親に

サブマップ側で右クリック → 「親マップに戻す」 → サブマップの内容が Container として吸収される (差分はマージ)。

注意

  • ⚠ サブマップ昇格中はそのスコープ外のエッジを引けない
  • ⚠ 親マップを保存しないと、サブマップの編集も同じ .hrf には保存されない

折りたたみと検索

折りたたまれた Container 内のノートも:

  • ✅ Outline パネルでは展開して見える
  • ✅ Ctrl + F 検索の対象になる (ヒット時に自動展開)
  • ❌ キャンバス上は隠れたまま

ネスト

Container の中に Container を入れられる。深さ制限なし。ただし 5 階層を超えると Outline 表示が見づらくなるので 3 階層以内推奨。

レイアウトヒント

layoutHint を tree-right にすると、子ノートを展開時に右方向ツリーで自動配置 (Reingold-Tilford 風)。手動配置を維持したい場合は freeform。

layoutHint配置用途
freeform手動 (既定)スクラップブック型
tree-down上から下へツリー階層図
tree-right左から右へツリーフロー図
radial中心から放射状マインドマップ古典型

Container 内で ⌨ Ctrl + Alt + G → 現在の hint で Auto Layout を即実行。

グループ化 (Frame との使い分け)

目的使うもの
視覚的に「ここまでが営業部のメモ」と囲みたいFrame
「営業部のメモ」5 個を一塊として動かしたいContainer
「営業部のメモ」を別の .hrf に分けたいレベルサブマップ昇格後、エクスポート

レイヤー (Layer)

Outline パネルの上部に「Layer」リスト。レイヤー単位で:

  • 表示 / 非表示
  • ロック (編集不可)
  • 色付け (レイヤーごとに半透明色を重ねる)

ノートとエッジはレイヤーに所属。新規作成時は アクティブレイヤー に入る。
