サービス起動 {#service-startup}

AI 機能は Python AI service を必要とする (stub 含む)。

自動起動 (既定)

アプリ起動時、ai_service/ を子プロセスで自動 spawn (port 8765)。Settings で OFF 可。

手動起動

cd C:\Users\geshtalt\dev\HrdayaFlow\ai_service
python -m uvicorn main:app --host 127.0.0.1 --port 8765 --app-dir src

ヘルスチェック: curl http://127.0.0.1:8765/health → {"status":"ok"}

接続確認

ステータスバー右の AI バッジ:

表示意味
🟢 AI 接続中OK
🟡 stub のみLLM 未接続、stub にフォールバック
🔴 AI 未接続service 未起動、AI 機能不可

テキスト → マップ {#text-to-map}

文章を投げると、ノート + エッジで構造化されたマップを返す。

使い方

  1. AI Panel を開く (右パネル切替 or Ctrl + Shift + A)
  2. テキストを貼り付け
  3. 「生成」ボタン or Ctrl + Enter
  4. プレビュー表示 → 「マップに挿入」 or 「キャンセル」

ストリーミング

WebSocket (/api/generate-map/stream) でチャンクごとに表示。長文でも 1 ノードずつ生えてくる。

入力形式の例

箇条書き (一番強い)

プロジェクトキックオフ
- 目的: ユーザー数 2 倍
- 期日: 2026-09 末
- 担当
  - 田中 (PM)
  - 佐藤 (eng)
- 課題
  - 競合の動き
  - 予算

→ 5 ノード + 5 エッジの階層マップに。

文章 (LLM 必須)

来期のキックオフは 2026-09 末。田中が PM、佐藤がエンジニアで、
ユーザー数を 2 倍にする目標。リスクは競合と予算。

→ stub では弱い。LLM では概念抽出してマップ化。

詳細フォーマット仕様

docs/ai-prompts/hrdaya-output-spec.md 参照。LLM プロンプトには「JSON のみで返答せよ」のテンプレ付き。

マップ → 要約 {#summarize}

マップを文章にする。出力先: クリップボード / 新規 Markdown ノート / ファイル。

使い方

  1. キャンバスで対象を選択 (空なら全マップ)
  2. メニュー → AI → 要約
  3. 文体選択: 箇条書き / 段落 / Twitter 280 字 / 1 行

内部処理

  • LLM ON → マップ JSON を整形して LLM に投げる
  • LLM OFF → rule-based summarize (ai_service/src/converter/map_to_summary.py)
    • ルートノート + 第 2 階層を箇条書き化

Suggest Edges {#suggest-edges}

マップ全体を見て、繋がっていない関連ノート間のエッジを提案。

使い方

メニュー → AI → エッジ提案 → ダイアログに候補一覧 → 個別 / 一括採用。

提案エッジ (12 件)
☑ 顧客 A → 営業フロー (信頼度 0.92)
☑ 顧客 B → 営業フロー (信頼度 0.88)
☐ 競合分析 → 顧客 A   (信頼度 0.41 - 低)
[ すべて採用 ] [ 選択を採用 ] [ キャンセル ]

LLM ON → 意味的類似度。LLM OFF → タイトル文字列の Jaccard 類似度。

Suggest Children {#suggest-children}

1 ノートに対して、その「展開候補」を提案。

使い方

ノート選択 → 右クリック → AI → 子を提案

"プロジェクトキックオフ" の子提案
☑ 目的
☑ 期日
☑ 担当者
☐ リスク
☐ 予算
[ 選択を追加 ]

Diff (構造比較) {#diff}

2 つのマップ (or 同マップの 2 時点) の差分を JSON Patch で取得。

用途

  • バージョン管理 (どこが変わったか)
  • 共同編集 (相手の変更を取り込み)
  • Undo 履歴の人間可読化

CLI

hrdaya diff before.hrf after.hrf > patch.json
hrdaya apply-patch base.hrf patch.json --output result.hrf

詳細: core/src/api.rs の generate_map_json_patch / apply_map_json_patch。

MCP Server (将来)

app/lib/mcp/ で HTTP ベースの MCP をホスト中 (v0.1.1 計画)。Claude Desktop / Cursor などから:

  • read() — マップ全体取得
  • find_node(id) — ノート 1 件取得
  • find_edge(from, to) — エッジ取得
  • bulk_apply(operations) — 一括変更
  • bulk_patch(json_patch) — JSON Patch 適用

詳細: docs/v0-1-1/c-mcp-tools/。

プロンプトテンプレート

ai_service/src/prompts/ に json/jp テンプレート群。Settings → AI → プロンプト編集 で個別カスタマイズ可。

例: 「文体は丁寧体」「絵文字を 1 ノートに 1 つ入れる」など。

エラーとフォールバック

状況動作
AI service 起動失敗AI 機能無効化、ステータス 🔴
LLM タイムアウト (30 秒)stub に自動フォールバック
LLM レスポンスが JSON 不正1 回だけリトライ → 失敗時 stub
ノート数 1000 超のマップを要約チャンク分割 → 結合

プライバシー

  • stub: ローカル完結、外部送信なし
  • Ollama: ローカル完結 (Ollama 自体がローカル LLM)
  • PrudeLLM: 外部送信。マップ内容が API 経由で送信される。Settings の「PrudeLLM 利用に同意」を ON にしないと使えない

動作確認チェックリスト

  • [ ] AI service が起動 (http://127.0.0.1:8765/health が ok)
  • [ ] AI バッジが 🟢 か 🟡
  • [ ] AI Panel で stub 選択 → テキスト → マップ生成
  • [ ] Ollama で同じテキストを生成 → 結果が違う
  • [ ] PrudeLLM で生成 (API キーあれば)
  • [ ] 要約 → クリップボードにコピー
  • [ ] エッジ提案 → 候補が出る
  • [ ] 子提案 → 候補が出る
  • [ ] LLM タイムアウトで stub にフォールバック
  • [ ] AI service 停止時に AI Panel が無効化される
